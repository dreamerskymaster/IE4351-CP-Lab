🤖 Introduction: What is Offline Robot Programming?

Welcome to the Offline Robot Programming Lab! This lab introduces you to modern industrial robotics and teaches you how to program robots without physically touching them.

What is "Offline" Programming?

Traditionally, robots are programmed using a teach pendant (a handheld controller) where you manually move the robot to each position and save those points. This is called online programming or teach pendant programming.

Offline programming means you create and test robot programs on a computer using simulation software before ever touching the real robot. Think of it like:

  • Video game analogy: Just like playing a racing game before driving a real car
  • Flight simulator: Pilots practice in simulators before flying real planes
  • CAD/CAM analogy: Similar to how you design parts in CAD and generate CNC programs in CAM

💡 Why Offline Programming?

Advantages over teach pendant programming:

  • No production downtime: The robot keeps working while you program the next job
  • Safer: You can test and debug in simulation without risk of crashes
  • Faster: Programming complex paths is much quicker in software
  • Better planning: You can see the entire cell and plan collision-free paths
  • Reusable: Save programs and modify them for similar tasks
  • Multi-robot: Easier to coordinate multiple robots working together

💡 What's a "Collaborative Robot" (Cobot)?

Unlike traditional industrial robots that are caged off for safety, collaborative robots are designed to work safely alongside humans. They have:

  • Force limiting: If they bump into something, they stop immediately
  • Rounded edges: No sharp pinch points
  • Speed monitoring: They slow down or stop when humans are nearby
  • Easy programming: Designed to be user-friendly

🔧 Robot Programming Basics

Understanding Robot Coordinate Systems

Before programming a robot, you need to understand how robots know where they are and where to move.

The Base Frame

💡 What is a Base Frame?

The base frame is the robot's "home" coordinate system. It's like the origin point (0,0,0) on a graph. Every position the robot moves to is measured from this point.

Think of it like this: If you're giving directions to your house, you might say "3 blocks north, 2 blocks east from the town center." The town center is like the base frame - everything is measured from there.

The Tool Center Point (TCP)

💡 What is TCP?

The Tool Center Point (TCP) is the reference point at the tip of whatever tool the robot is holding. For a gripper, it's usually at the center of the gripper jaws. For a welding torch, it's at the tip of the electrode.

Why it matters: When you tell the robot to move to a position, you're actually moving the TCP to that position, not the robot's wrist or base.

Types of Robot Motion

1. Point-to-Point (PTP) Motion

What it does: Moves the robot from current position to target position by the fastest route

How it works: Each joint moves at its own speed to reach the target simultaneously

Path: The TCP does NOT move in a straight line! The path is unpredictable.

When to use it:

  • Moving between widely separated positions
  • When the exact path doesn't matter
  • When you need the fastest movement
  • Moving to "approach" positions before a precise operation

⚠️ PTP Safety Warning

Because the path is unpredictable, PTP motion can cause collisions if obstacles are in the way. Always use PTP for moves in open space, not near objects!

2. Linear Motion

What it does: Moves the TCP in a perfectly straight line from start to end

How it works: The robot calculates joint movements to make the TCP follow a linear path

Path: Predictable straight line

When to use it:

  • Approaching/retracting from pick or place positions
  • When precision path control is needed
  • Moving near obstacles where collision is a risk
  • Any operation where the path matters (welding, gluing, etc.)

✅ General Rule of Thumb

  • Use PTP for: Long moves in open space, going "home", moving between work areas
  • Use Linear for: Final approach to pick/place, retracting from positions, moves near objects

Understanding the Pick and Place Task

The classic beginner robot task is pick and place. The robot picks up an object from one location and places it at another location. Simple, but it teaches all the fundamentals!

The Five Key Points (Waypoints)

Point Name Purpose Motion Type
A Home Position Safe starting/ending position, out of the way PTP
B Approach Pick Above the pick position, ready to descend PTP (from A), Linear (to C)
C Pick Position Exact location to grab the part Linear
D Approach Place Above the place position, ready to descend PTP (from B), Linear (to E)
E Place Position Exact location to release the part Linear

💡 Why Five Points Instead of Two?

You might think: "Why not just go directly from pick to place?" Here's why the intermediate points are critical:

  • Collision avoidance: The approach points (B and D) ensure the robot approaches from above, avoiding obstacles
  • Controlled descent: Using Linear motion from B to C ensures a straight, safe approach
  • Repeatability: Having defined approach points makes the program more reliable
  • Safety: If something goes wrong, the robot is more likely to be in a safe position

The Complete Sequence

📋 Step-by-Step Pick and Place Sequence

  1. Start at Home (Point A) - Robot in safe position, gripper open
  2. Open Gripper - Ensure gripper jaws are open (call subprogram)
  3. Move to Approach Pick (Point B) - PTP motion to position above part
  4. Descend to Pick (Point C) - Linear motion straight down to part
  5. Close Gripper - Grab the part (call subprogram)
  6. Retract to Approach (Point B) - Linear motion straight up
  7. Move to Approach Place (Point D) - PTP motion to position above target
  8. Descend to Place (Point E) - Linear motion straight down
  9. Open Gripper - Release the part (call subprogram)
  10. Retract to Approach (Point D) - Linear motion straight up
  11. Return Home (Point A) - PTP motion back to starting position

What is OCTOPUZ?

OCTOPUZ is professional offline robot programming software used by companies worldwide. It allows you to:

  • Create virtual robot cells with accurate 3D models
  • Program robots using a graphical interface
  • Simulate and verify programs before deployment
  • Export programs for different robot brands (Universal Robots, FANUC, ABB, KUKA, etc.)
  • Detect collisions and optimize robot paths

Main Workspaces in OCTOPUZ

Workspace Purpose What You Do Here
HOME Cell setup and overview View cell components, show/hide objects, manage the overall environment
PROGRAM Create and edit robot programs Write motion statements, jog the robot, test positions, simulate programs
EXPORT Generate robot code Export programs in brand-specific formats (.urp, .LS, etc.)

Key Tools and Menus

1. Cell Graph

What it is: A hierarchical list of all objects in your robot cell

What you can do:

  • Show/hide components (like cages, safety enclosures)
  • Select robots, tools, fixtures
  • Organize your workspace
Common task: Hiding the safety cage
  1. Click on "Cell Graph" in the HOME workspace
  2. Find "Hood" or "Cage" in the list
  3. Click the eye icon to hide it
  4. Now you can see the robot clearly!

2. Program Editor

What it is: The main area where you write your robot program

What you can do:

  • Add motion statements (PTP, Linear)
  • Insert I/O commands (turn things on/off)
  • Call subprograms
  • Copy/paste/delete program lines
  • Reorder statements by dragging

3. Jog Menu

What it is: Controls for manually moving the robot in simulation

What you can do:

  • Move individual joints (Joint mode)
  • Move in world coordinates X, Y, Z (World mode)
  • Move relative to the tool (Tool mode)
  • Rotate around tool axes (Rx, Ry, Rz)
  • Select which tool is active

✅ Jogging Tips

  • Start in World mode: Easier to understand (X=left/right, Y=forward/back, Z=up/down)
  • Use small increments: Start with 1mm or 5mm movements when near objects
  • Watch the robot: Keep an eye on the 3D view as you jog
  • Undo is your friend: Made a mistake? Use Ctrl+Z to undo!

4. Point Editor

What it is: Detailed view of position data for each waypoint

What you can see:

  • X, Y, Z coordinates (in millimeters)
  • Rotation angles (Rx, Ry, Rz in degrees)
  • Joint angles (J1, J2, J3, J4, J5, J6)
  • Reference frame (World, Base, Tool)

5. Statement Properties

What it is: Settings for each motion statement in your program

What you can adjust:

  • Speed: How fast the robot moves (usually % of maximum)
  • Acceleration: How quickly the robot speeds up/slows down
  • Blend radius: How smoothly the robot transitions between points
  • Reference frame: Which coordinate system to use

Understanding Subprograms

💡 What are Subprograms?

Think of subprograms like functions in coding. Instead of writing the same code over and over, you create a reusable block of code that you can "call" whenever needed.

Example: Instead of writing the commands to open the gripper 10 times in your program, you create an "openGripper" subprogram once, then call it whenever you need to open the gripper.

Common Subprograms in This Lab:

Subprogram Purpose When to Call It
openGripper Opens the gripper jaws Before picking up a part, after placing a part
closeGripper Closes the gripper jaws After positioning at the pick location
VACUUMON Turns on vacuum suction When using vacuum gripper to pick parts
VACUUMOFF Turns off vacuum suction When releasing parts from vacuum gripper
pickLocationPallet Pre-saved pick position Reference for where to pick parts from pallet
pickLocation2 Pre-saved place position Reference for where to place parts in fixture

How to Use Subprograms:

Calling a subprogram:
  1. In the Program Editor, find the subprogram in the subprogram list
  2. Click on the subprogram to open it and see what it does
  3. Copy all the lines from the subprogram
  4. Paste them into your Main program at the appropriate location
  5. The commands will execute in sequence when the program runs

Simulation and Verification

One of the most powerful features of OCTOPUZ is the ability to test your program before running it on the real robot.

Running a Simulation:

  1. Play button: Click to run the entire program from start to finish
  2. Step forward: Execute one statement at a time (good for debugging)
  3. Speed control: Adjust simulation speed (slow it down to watch carefully)
  4. Collision detection: OCTOPUZ will highlight if the robot hits anything

✅ Simulation Best Practices

  • Always simulate before exporting! Catch errors in software, not on the real robot
  • Run it multiple times: Watch from different camera angles
  • Check for near-misses: Even if there's no collision, is the robot too close to objects?
  • Verify gripper operation: Make sure open/close happens at the right time
  • Use step mode: When debugging, step through line-by-line

🔵 Programming the UR5e Robot

Your Task: Transfer Phone Cases

For the UR5e robot, you'll program it to pick up small cellphone cases from a part carrier and place them into an assembly fixture. This simulates a real manufacturing assembly operation!

Step-by-Step Programming Guide

Step 1: Open the Project File
  1. Download URCell_Lab_PNP.vcmx to your computer
  2. Open OCTOPUZ software
  3. File → Open → Select the .vcmx file
  4. Wait for the project to load (may take 30-60 seconds)
Step 2: Explore the Cell (HOME Workspace)
  1. You'll see a complete robot assembly cell in 3D
  2. The robot is inside a safety cage called "Hood"
  3. To see the robot better:
    • Click on Cell Graph (usually on the left side)
    • Find "Hood" in the component list
    • Click the eye icon next to it to hide the cage
    • Now you can see the UR5e robot clearly!
  4. Take a moment to explore - rotate the 3D view, zoom in/out
Step 3: Switch to PROGRAM Workspace
  1. Click on "PROGRAM" at the top of the screen
  2. This is where you'll write your robot program
  3. Notice the Program Editor on the left side
  4. The 3D view is in the center
  5. Properties and settings are on the right
Step 4: Verify Tool Setup
  1. Open the Jog menu (usually at the top)
  2. Check that "StandardGripper" is selected as the Tool
  3. This tells OCTOPUZ which end-effector the robot is using
  4. The base frame and tool frame are already set up for you (pre-configured)

💡 What are Base and Tool Frames?

Base Frame: Defines where the robot's coordinate system starts (usually at the robot base)

Tool Frame: Defines the Tool Center Point (TCP) - the reference point at the gripper tip

For this lab, these are already configured. In real applications, you'd need to set these up yourself!

Step 5: Create Point A (Home Position)
  1. In the Program Editor, click Add Statement → PTP Motion
  2. A new motion statement appears in your program
  3. The robot might move to a default position
  4. Use the Jog controls to move the robot to a safe "home" position:
    • Away from the part carrier and assembly fixture
    • All joints in comfortable positions
    • Easy to see and access the work area
  5. Optional: Save this as your home state:
    • Click the gear icon at the top center
    • Click "Save State"
    • Now you can return to this position anytime!
Step 6: Open the Gripper
  1. Before picking anything, the gripper must be open!
  2. In the Program Editor, look for the subprogram list
  3. Click on openGripper subprogram
  4. You'll see the commands inside (usually I/O digital output commands)
  5. Select all the lines in the subprogram
  6. Copy them (Ctrl+C)
  7. Go back to your Main program
  8. Paste (Ctrl+V) after your home position statement

💡 Understanding I/O Commands

I/O stands for Input/Output. These are digital signals the robot sends to control external devices:

  • Digital Output = ON: Sends a signal (like pressing a button)
  • Digital Output = OFF: Stops the signal (like releasing a button)
  • The gripper has a control board that receives these signals and opens/closes the jaws
Step 7: Create Point B (Approach Pick Position)
  1. This point MUST be directly above Point C (the pick position)
  2. Here's the trick to ensure they're aligned:
    • First, go to the exact pick position (Point C)
    • Then, move only in Z (upward) to create Point B
    • This guarantees B and C differ only in height
  3. How to do it:
    • Open the pickLocationPallet subprogram
    • Copy the PTP Motion Statement from it
    • Paste it into your Main program
    • This moves the robot to Point C (the pick position)
  4. Now create Point B:
    • In Statement Properties, select World coordinate system
    • Use Jog menu to move ONLY in +Z direction (upward)
    • Move to a safe height (maybe 50-100mm above the part)
    • Click the red circle "Touch Up" button to save this as Point B

⚠️ Why Point B Must Be Above Point C

If Point B and C are not vertically aligned:

  • The robot might sweep sideways and hit the part carrier
  • Could knock over parts or damage the fixture
  • The approach would not be predictable or safe

Always use Linear motion from B to C to ensure a straight vertical descent!

Step 8: Create Point C (Pick Position)
  1. Open the pickLocationPallet subprogram again
  2. Copy the PTP Motion Statement
  3. Paste it into your Main program (after Point B)
  4. Important: Change it from PTP to Linear Motion:
    • Click on the statement
    • Change motion type to "Linear"
    • This ensures the robot descends straight down from B to C
Step 9: Close the Gripper
  1. Now that the robot is at the pick position, grab the part!
  2. Find the closeGripper subprogram
  3. Copy all lines from it
  4. Paste into your Main program (after Point C)
  5. The gripper will close and hold the part
Step 10: Return to Point B (Retract)
  1. After grabbing the part, lift straight up
  2. Click on Point B in your program
  3. Add a new Linear Motion statement
  4. Drag it to the end of the program (or copy/paste)
  5. This retracts the robot straight up with the part
Step 11: Create Point D (Approach Place Position)
  1. Just like Point B, Point D must be directly above Point E
  2. First, move to Point E:
    • Open pickLocation2 subprogram
    • Copy the PTP Motion Statement
    • Paste to Main program
    • Change to Linear Motion
  3. Now create Point D:
    • Jog upward (+Z) to a safe height
    • Touch up the point
    • This is your approach to the place position
Step 12: Create Point E (Place Position)
  1. Open pickLocation2 subprogram
  2. Copy the PTP Motion Statement
  3. Paste into Main program
  4. Change to Linear Motion
  5. This is where the robot will place the part
Step 13: Open the Gripper (Release Part)
  1. Now release the part at the place position
  2. Copy the openGripper subprogram
  3. Paste into Main program
  4. The part is now placed in the assembly fixture!
Step 14: Retract to Point D
  1. Move straight up from the place position
  2. Click on Point D
  3. Add a new Linear Motion statement
  4. Move it to the end of the program
Step 15: Return Home
  1. Finally, return to the home position (Point A)
  2. Add a PTP Motion statement
  3. If you saved the home state earlier, recall it
  4. Otherwise, manually jog back to home and touch up
  5. This completes one pick and place cycle!

Testing Your Program

Simulation Checklist:
  1. Click the Play button to run the simulation
  2. Watch carefully for:
    • Collisions with the part carrier, fixture, or table
    • Gripper opening/closing at the right times
    • Smooth transitions between points
    • Robot staying within its work envelope
  3. If there are errors:
    • Identify which statement causes the problem
    • Adjust the position or motion type
    • Re-simulate until it's perfect
  4. Run the simulation at least 3 times from different viewing angles

✅ Common Mistakes to Avoid

  • Using PTP near objects: Always use Linear motion when close to the part or fixture
  • Forgetting to open gripper: Make sure the gripper is open before trying to pick
  • Points not aligned: B must be directly above C, D must be directly above E
  • Approach height too low: Give yourself plenty of clearance (50mm minimum)
  • Not simulating enough: Test thoroughly before exporting!

Program Structure Overview

📝 Your Final Program Should Look Like This:

1.  PTP Motion to Point A (Home)
2.  Call openGripper subprogram
3.  PTP Motion to Point B (Approach Pick)
4.  Linear Motion to Point C (Pick Position)
5.  Call closeGripper subprogram
6.  Linear Motion to Point B (Retract)
7.  PTP Motion to Point D (Approach Place)
8.  Linear Motion to Point E (Place Position)
9.  Call openGripper subprogram
10. Linear Motion to Point D (Retract)
11. PTP Motion to Point A (Return Home)

🟢 Programming the FANUC CR-7iA/L Robot

Your Task: Coaster Pick and Place

For the FANUC robot, you'll program a simpler task: pick up a coaster from one side of a table and place it on the other side. This teaches you the same concepts but with a different robot brand.

What Makes the FANUC Different?

💡 7-Axis vs. 6-Axis Robots

Most industrial robots have 6 axes (like the UR5e). The FANUC CR-7iA/L has 7 axes!

What does the extra axis do?

  • More flexibility: Can reach around obstacles
  • Multiple solutions: Can reach the same point in different ways (like how you can scratch your back with either hand)
  • Avoid singularities: Less likely to get "stuck" in problematic positions
  • Better for confined spaces: Can maneuver in tight areas

The tradeoff: Slightly more complex to program and control

FANUC Programming Differences

Feature Universal Robots UR5e FANUC CR-7iA/L
End-Effector Gripper (mechanical jaws) Vacuum suction cup
Subprograms openGripper / closeGripper VACUUMON / VACUUMOFF
Export Format .urp (directly usable) .LS (must convert to .TP)
Programming Style Very intuitive, user-friendly More industrial, traditional FANUC style
Extra Step None Requires ROBOGUIDE post-processing

Step-by-Step FANUC Programming

Step 1: Open the FANUC Project
  1. Download CR7_Lab_PNP.vcmx to your computer
  2. Open it in OCTOPUZ
  3. Navigate to the PROGRAM workspace
  4. Notice this cell is simpler - just a table with the robot
Step 2: Program the Pick and Place Sequence
  1. Follow the same 5-point strategy:
    • Point A: Home position (away from the table)
    • Point B: Above the coaster on the left side
    • Point C: At the coaster (to pick it up)
    • Point D: Above the target location on the right side
    • Point E: At the target location (to place it down)
  2. Remember:
    • Use PTP for moves between widely separated points (A→B, B→D, D→A)
    • Use Linear for approaches and retracts (B→C, C→B, D→E, E→D)
Step 3: Control the Vacuum Gripper
  1. Instead of openGripper/closeGripper, use:
    • VACUUMON - Turn on suction (call this at Point C after positioning)
    • VACUUMOFF - Turn off suction (call this at Point E after placing)
  2. Insert these subprogram calls at the appropriate locations in your program

💡 How Vacuum Grippers Work

A vacuum gripper uses suction (negative air pressure) to hold parts, similar to how a vacuum cleaner picks up dirt:

  • VACUUMON: Turns on the vacuum pump, creating suction at the suction cup
  • Contact: When the cup touches the part, the vacuum holds it firmly
  • VACUUMOFF: Releases the vacuum, the part drops or stays in place
  • Best for: Flat parts, non-porous materials (plastic, metal, glass)
Step 4: Collision Check
  1. This is CRITICAL for the FANUC robot!
  2. The suction gripper extends down from the robot wrist
  3. Make sure the gripper doesn't hit the table surface
  4. In simulation:
    • Watch the gripper body, not just the suction cup
    • Zoom in to check clearances
    • Rotate the view to see from different angles
  5. If there's a collision risk, adjust Point C and E heights
Step 5: Complete and Verify
  1. Your final program should have the same structure as the UR5e program
  2. Run the simulation multiple times
  3. Test at different speeds (slow and full speed)
  4. Verify no collisions occur
  5. Check that vacuum turns on/off at the right times

Program Structure for FANUC

📝 FANUC Program Structure:

1.  PTP Motion to Point A (Home)
2.  Call VACUUMOFF subprogram (ensure vacuum is off)
3.  PTP Motion to Point B (Approach Pick)
4.  Linear Motion to Point C (Pick Position - coaster)
5.  Call VACUUMON subprogram (turn on suction)
6.  [Optional: Add a short delay to ensure vacuum stabilizes]
7.  Linear Motion to Point B (Retract with coaster)
8.  PTP Motion to Point D (Approach Place)
9.  Linear Motion to Point E (Place Position)
10. Call VACUUMOFF subprogram (release coaster)
11. Linear Motion to Point D (Retract)
12. PTP Motion to Point A (Return Home)

🚀 Exporting and Deploying Your Programs

Exporting from OCTOPUZ

Once your simulation is perfect, you need to export the program in a format the real robot can understand.

Universal Robots UR5e Export Process

Step 1: Export the Program
  1. In OCTOPUZ, click Export → Code → Robot Code
  2. Select .urp as the file format
  3. Choose a save location and give it a descriptive name (e.g., "phone_case_transfer.urp")
  4. Click Export
Step 2: Transfer to Robot
  1. Copy the .urp file to a USB flash drive
  2. Insert the USB drive into the UR5e teach pendant
  3. On the teach pendant:
    • Go to Program menu
    • Click "Load Program"
    • Navigate to USB drive
    • Select your .urp file
  4. The program loads directly - ready to run!

FANUC CR-7iA/L Export Process (More Steps)

Step 1: Export from OCTOPUZ
  1. Click Export → Code → Robot Code
  2. Select .LS as the file format (FANUC LS format)
  3. Save the file with a descriptive name (e.g., "coaster_transfer.LS")
Step 2: Post-Process with ROBOGUIDE
  1. Copy the .LS file to a USB drive
  2. Take it to the lab computer (with ROBOGUIDE installed)
  3. Ask the lab TA to help with this step!
  4. ROBOGUIDE converts .LS to .TP (FANUC teach pendant format)
  5. This conversion:
    • Optimizes the code for the specific FANUC controller
    • Adds any required FANUC-specific commands
    • Converts coordinate formats
Step 3: Load to Robot
  1. Put the .TP file on your USB drive
  2. Insert USB into the FANUC teach pendant
  3. The TA will help you load and run the program
  4. FANUC robots have more complex safety systems - always have supervision!

💡 Why the Extra Step for FANUC?

Different robot brands use different programming languages and file formats:

  • Universal Robots: Uses URScript, .urp files are directly executable
  • FANUC: Uses Karel and TP (teach pendant) language, requires compilation
  • ROBOGUIDE: FANUC's official software for program conversion and simulation

This is like how different video game consoles need different game formats!

Running Programs on the Physical Robots

🚨 CRITICAL SAFETY FOR PHYSICAL ROBOTS

When running on real robots:

  • Always have a TA present - they will supervise and can hit emergency stop
  • Start at reduced speed: 10-25% of programmed speed for first run
  • Test in manual mode first: Step through the program line by line
  • Stay alert: Keep your hand near the emergency stop
  • Clear the area: Make sure no one is in the robot's reach
  • Expect differences: The real robot might not behave exactly like the simulation

Universal Robots UR5e - Running the Program

  1. Load the program (as described above)
  2. Check the installation: Make sure the gripper and parts are set up correctly
  3. Switch to Manual mode on the teach pendant
  4. Test at reduced speed: Set speed slider to 10%
  5. Press Play and watch carefully
  6. If successful, gradually increase speed to 25%, 50%, then 100%

FANUC CR-7iA/L - Running the Program

  1. TA will load the program to the robot controller
  2. Safety check: Verify the work area is clear
  3. TA will run in T1 mode (teach mode with reduced speed)
  4. Step-by-step execution: The program will run one line at a time
  5. Observation: Watch how the robot performs each motion
  6. If successful, TA may run at higher speed or in Auto mode

✅ Debugging Physical Robot Programs

If the program doesn't work perfectly on the real robot:

  • Common issue #1 - Position offsets: Points might be slightly off due to calibration differences
    • Solution: Use teach pendant to adjust positions slightly
  • Common issue #2 - Speed too fast: Robot moves too aggressively
    • Solution: Reduce speed in program or use speed override
  • Common issue #3 - Gripper timing: Opens/closes at wrong time
    • Solution: Add small delays (Wait commands) before/after gripper operations
  • Common issue #4 - Near collisions: Robot comes too close to objects
    • Solution: Increase approach heights, adjust positions

🎓 Understanding the Technology

How Do Robots Know Where They Are?

🔍 Robot Position Sensing

Industrial robots use encoders on each joint to measure position:

  • Encoder: A sensor that counts motor shaft rotations
  • Resolution: Can detect tiny movements (micrometers)
  • Feedback loop: Controller constantly reads encoder values
  • Position calculation: Using known gear ratios and arm lengths, the controller calculates exactly where the TCP is in 3D space

This is called "forward kinematics": Given joint angles, calculate TCP position

How Do Robots Plan Their Movements?

🔍 Inverse Kinematics

When you tell a robot to move to a position, the controller must figure out what angle each joint should be at:

  • The problem: "I want the TCP at X=100, Y=200, Z=300. What should joints 1-6 be?"
  • The solution: Complex mathematical calculations (inverse kinematics)
  • Multiple solutions: Often there are several ways to reach the same point!
  • Robot chooses: Based on which solution is closest to current position, or has no collisions

Why 7 axes help: The FANUC's 7th axis provides even more solution options!

Best Practices for Clean Programs

✅ Professional Programming Habits

  1. Name your points clearly: Use descriptive names (Home, ApproachPick, PickCoaster, etc.)
  2. Comment your code: Add notes explaining what each section does
  3. Consistent approach heights: Use the same clearance height for all approach/retract moves

  6. Test incrementally: Build and test your program in sections, not all at once

🧠 Quiz Preparation Hints

💡 How to Use These Hints

Re-read the indicated sections of this guide, then use your understanding to answer your quiz questions. These hints point you in the right direction — they don't give away the answer directly.

✅ Hint — Question 1: Tool Center Point (TCP)

Core concept: What happens when the TCP is defined incorrectly in OCTOPUZ?

  • Re-read the "What is TCP?" info box in the Robot Programming Basics section.
  • Think about what OCTOPUZ actually uses the TCP definition for when computing robot motion paths.
  • Direction: An incorrect TCP shifts all computed tool paths away from their intended targets. The robot calculates motion from a wrong reference point — this error appears on the real robot (not just in simulation rendering), and the robot cannot self-correct for a misconfigured TCP.

✅ Hint — Question 2: Why We Specify the Robot Base Frame

Core concept: Why is setting the correct base frame essential in OCTOPUZ?

  • Re-read the "What is a Base Frame?" info box in the Robot Programming Basics section.
  • Consider: every position, reachability check, collision envelope, and coordinate transformation is measured relative to the base frame.
  • Direction: Without the correct base, OCTOPUZ cannot properly transform CAD toolpaths into real joint motions. It also cannot correctly place fixtures, tooling, and workcell geometry. All downstream spatial calculations depend on this foundation.

✅ Hint — Question 3: Point-to-Point vs. Linear Motion

Core concept: What is the defining difference between PTP and Linear motion?

  • Re-read the full "Types of Robot Motion" subsections (both PTP and Linear) in the Robot Programming Basics section.
  • Focus on: which type constrains the TCP to a straight Cartesian path vs. which lets each joint move independently at its own speed.
  • Direction: PTP = fastest, joint-space motion (TCP follows an unpredictable arc). Linear = straight-line TCP path (predictable, used for approaches and retracts near objects). Think about which one you must use when descending from Point B to Point C.
